# Class 14 Final Demo Builder

## Purpose
Use this Class 14 skill when a student needs help turning an already-built website, assistant, lead capture, CRM, and sales workflow into a simple final demo.

The goal is to produce:
- final demo objective
- recommended demo order
- exact scenes to show
- presenter script or talking points
- backup plan if one module fails live

## Core principle
The best Class 14 demo is not the most complex demo.

It should be:
- simple
- believable
- easy to explain
- clearly connected to revenue

## Demo target flow
The default Class 14 demo should show this path:
website -> AI assistant -> lead capture -> CRM / follow-up -> quote / proposal / next step

If content / SEO / GEO / short video exists, mention it briefly at the start as the traffic source, but do not let it dominate the demo.

## Input checklist
Collect or infer when available:
- business type
- target customer
- main offer
- website pages available
- assistant status
- lead capture status
- CRM status
- follow-up or sales assets available
- pricing / proposal asset available
- live modules versus mock/demo-only modules

If something is missing, redesign the demo around the narrowest believable working path.

## Required demo structure
### Part 1 — Business context
Explain briefly:
- who the business serves
- what offer is sold
- how leads enter the system

### Part 2 — Website demonstration
Show:
- homepage
- offer / service page
- CTA or contact action

### Part 3 — AI assistant demonstration
Show 2-3 realistic questions, such as:
- what services do you offer
- who is this for
- how does pricing work
- what is the next step

### Part 4 — Lead capture demonstration
Show:
- form submit
or
- assistant-guided contact action

### Part 5 — CRM / follow-up demonstration
Show:
- where the lead appears
- what status or note is created
- what the next follow-up action is

### Part 6 — Quote / proposal / next-step demonstration
Show one of:
- pricing summary
- quote draft
- proposal template
- consultation booking next step

## Demo rules
- Keep the final demo within 5-8 minutes unless the user requests a longer version.
- Prefer one complete path over many partial modules.
- Distinguish clearly between live-working modules and simulated demo-only modules.
- If the CRM is not real yet, say it is a demo representation rather than pretending it is live.

## Failure handling
Always include backup suggestions for:
- assistant answering badly
- form not submitting
- CRM not loading
- proposal asset not ready

Typical fallback:
- pre-load key pages
- use one prepared lead example
- use one prepared CRM screenshot or record
- use one prepared proposal sample

## 现场失败时的备用方案
## 演示后收尾话术

- Do not overcomplicate the demo.
- Do not treat non-working automations as live production systems.
- Make sure the demo ends with a business next step, not just a tool showcase.
