# Class 14 统一输出规范（中文）

## 目的
这份规范是 Class 14 相关技能的统一标题与结构标准。

适用范围：
- `class14-output-package-builder`
- `class14-teacher-workflow-orchestrator`
- `class14-classroom-master-prompt-builder`
- `final-integration-launch-orchestrator`
- 以及未来任何会输出 Class 14 最终交付包、老师主提示词、课堂 handoff 包的相关 skill

目标：
- 保证所有 Class 14 相关输出标题一致
- 保证输出顺序一致
- 保证“课程回顾”和“AI 一人公司总结桥接”固定出现在最前面
- 避免不同 skill 各写各的标题，导致课堂材料不统一

---

## 唯一标准标题顺序
所有 Class 14 最终打包输出，默认必须使用以下标题顺序：

```markdown
## 第 14 课重点回顾
## 如何把这些信息用于 AI 一人公司总结
## 第 14 课整体结论
## 学员当前系统状态摘要
## 端到端业务流程结论
## 阻塞项优先级
## 最终演示方案摘要
## Demo 证明材料与备用方案摘要
## 未来 30 天启动计划摘要
## 每周运营 SOP 摘要
## 课后唯一重点作业
## 下次复盘检查点
## 风险与假设
```

这是 Class 14 最终输出包的 canonical structure。
任何相关 skill 如果生成的是最终交付包、课堂总结包、老师 handoff 包，都应优先遵守这套标题。

---

## 每个标题的含义
### 1. 第 14 课重点回顾
作用：先提醒老师和学员，这节课的核心不是加功能，而是整合、验证、演示、启动、handoff。

要求：
- 2-4 条为宜
- 必须短
- 必须与当前学员案例相关
- 不能写成泛泛课程理论

### 2. 如何把这些信息用于 AI 一人公司总结
作用：把课程分析翻译成经营语言，说明这些模块如何构成 AI 一人公司的真实链路。

要求：
- 强调模块如何连成经营路径
- 重点看流量 -> 网站 -> 助手 -> 留资 -> CRM -> 跟进 -> 报价/提案
- 必须短、实用、贴合当前系统

### 3. 第 14 课整体结论
作用：给出一句话 readiness 判断。

常见格式：
- Demo Ready / Launch Ready / 两者都未完成
- 可演示但未稳定启动
- 窄链路成立，但仍需补关键断点

### 4. 学员当前系统状态摘要
作用：压缩当前系统现实状态。

至少覆盖：
- 业务类型
- 目标客户
- 最强模块
- 最弱模块
- 最影响成交的缺口

### 5. 端到端业务流程结论
作用：说明主链路是否成立，以及断点在哪里。

至少覆盖：
- 当前主链路
- 已打通环节
- 未打通关键环节
- 最强链路
- 最弱链路
- 最关键断点
- 最需要优先修复的 transition

### 6. 阻塞项优先级
作用：按 P0 / P1 / P2 排序，而不是列一堆杂项。

要求：
- 优先业务阻塞
- 页面美化默认不能高于成交断点
- 标题固定叫“阻塞项优先级”

### 7. 最终演示方案摘要
作用：把 Demo 压缩成老师可讲、学生可演示的可信流程。

要求：
- 说明 Demo 目标
- 给出 live 顺序
- 给出结束收尾话术
- 不要求长脚本，重点是可信闭环

### 8. Demo 证明材料与备用方案摘要
作用：降低 live 风险。

至少覆盖：
- 必须 live 的项
- 建议 backup 的项
- 当前还缺的证明材料
- 若现场失败，备用方案

### 9. 未来 30 天启动计划摘要
作用：把课后启动动作压成 4 周节奏。

### 10. 每周运营 SOP 摘要
作用：把系统从项目变成可重复运营动作。

### 11. 课后唯一重点作业
作用：防止布置太多并行任务。

要求：
- 只给一个核心作业
- 拆成 3 个具体行动项
- 明确完成标准、证明材料、截止时间

### 12. 下次复盘检查点
作用：方便老师和学员下次续接。

### 13. 风险与假设
作用：明确哪些判断依赖当前假设，哪些地方仍需确认。

---

## 标题命名统一规则
后续 skill 不要再混用下面这些旧写法，除非只是中间分析步骤，不是最终输出标题：

不推荐旧写法 -> 统一新写法：
- `当前系统整合结论` -> `第 14 课整体结论`
- `端到端业务流程检查` -> `端到端业务流程结论`
- `缺口与阻塞项` -> `阻塞项优先级`
- `最终演示清单` -> `最终演示方案摘要`
- `未来 30 天启动计划` -> `未来 30 天启动计划摘要`
- `每周运营 SOP` -> `每周运营 SOP 摘要`
- `课后作业` -> `课后唯一重点作业`

说明：
- skill 内部流程阶段可以保留“检查 / 审计 / 清单”等说法
- 但最终交付包标题应统一为这份规范的标准标题

---

## 使用规则
### 什么时候必须遵守这份规范
以下场景必须优先遵守：
- 最终课堂 handoff 包
- 学员课后带走的总结包
- 老师 Class 14 总控 prompt 的最终输出格式
- final integration summary 的最终打包输出
- 任何准备横向复用的 Class 14 中文模板或示例

### 什么时候可以不完全照搬
以下场景可以暂时扩展，但不应破坏最终打包标题：
- skill 内部分析步骤
- 模块审计明细
- 老师课堂现场笔记
- 单独的 demo 设计文档

如果需要额外内容，建议放在最终标准结构之外，或作为中间过程，不要改动最终 13 个标题。

---

## 推荐维护方式
- 把 `class14-output-package-builder` 视为 canonical source
- 其他 Class 14 相关 skills 在写最终输出结构时，应引用这份规范
- 以后如果新增或修改标题，先改这份规范，再同步改模板、示例、主 skill 文本

---

## 维护检查清单
每次修改相关 skill 后，至少检查：
1. 是否保留了前两个 opening sections
2. 标题顺序是否一致
3. 标题命名是否一致
4. 模板、示例、SKILL.md 是否同步
5. 是否把中间分析标题误当成最终交付标题

---

## 一句话维护原则
Class 14 的最终中文交付包，应始终先讲“这节课真正学到了什么”，再讲“这如何变成 AI 一人公司的经营总结”，然后再进入 readiness、流程、阻塞、Demo、启动、SOP、作业与复盘。
